# CTRL PULSE — DAILY CONTENT PRODUCTION SOP (v1.0)

**Effective:** 2026-11-12. **Page:** CTRL Pulse, Facebook Page `1434597583074408`. **Timezone:** `Africa/Casablanca`. **Status:** adopted by the enabled daily CTRL PULSE automation.

## Objective and deliverables

Each successful daily run **creates, QA-checks, publishes and verifies three separate assets on distinct subjects**:

1. **Narrated Facebook Reel:** A researched visual story, English TTS, native **1080×1920+** H.264/AAC, **30 FPS or better**, with meaningful animated actions, mandatory kinetic explanatory titles/callouts/labels, and no verbatim speech captions or subtitle tracks.
2. **Original Feed Image Post:** An attractive **1080×1350** visual with one useful insight, an original English description and reputable cited sources.
3. **Vertical Facebook Story:** An original **1080×1920** visual (tip, poll, teaser or question) in story-safe zones, separately verified.

If any item fails quality or publishing gates, **report that item's actual status** and keep it a draft. Never publish text-only filler or claim a queue receipt proves publication.

## 01. Research and rights gate — before art

- Inspect the connected Page's feed and pending queue for duplicate topics and posts; confirm Page ID.
- Select **three different** subjects appropriate to CTRL Pulse (useful technology, tools, science, creator software, cybersecurity, innovation).
- Verify external claims from **primary reliable sources**; preserve exact dates, caveats, pricing/licensing if relevant, and source URLs.
- Actively identify authentic, permitted source images or demonstration footage; record authorship, reuse license/permissions, relevance, and attribution.
- Do not generate fake app interfaces, source documents, photographs of supposed real events, test results, or headlines. Clearly distinguish **AI illustrations** from real documentary evidence.

## 02. Story-driven Reel — narrative gate

Begin with a story thesis and a concise English narration script, **not random clips**. The story must have **hook → setup → causal mechanism/problem → consequence or reversal → memorable payoff**. Match each spoken claim to an actual scene or object action.

Shot/beat manifest (adjust length as topic requires):

| Beat | Editorial role | Animated behavior |
| --- | --- | --- |
| 0–3s hook | Break an assumption / pose a striking question | Immediate visual transformation with a strong animated hook headline |
| Setup | Orient the viewer | Establish the object, physical location and stakes |
| Mechanism | Reveal how the system works | Animate actual process trajectories, connections, pieces and cause/effect with moving explanatory labels |
| Complication | Show what can go wrong or why it matters | Physical change, contrast, breakdown, counterexample |
| Payoff | Resolve the first question and supply insight | Visual callback, completion, transformation or repaired system |

**Voice:** generate natural **ENGLISH** TTS using a licensed/available voice; listen and check pronunciation, voice speed, peaks and duration. Do not impersonate real people. Keep narration central, with fitting SFX/music underneath.

## 03. Image, motion and asset pipeline

- Generate **at least four different scene images** (ideally 4–6), not a single image or a visually unrelated slideshow.
- Generate **1–3 multi-object asset sheets** with separated icons/characters/devices/equipment; cut them by code into reusable objects with transparent masks.
- Use generated GIF/action sequences where helpful; inspect all frames for continuity. Supplement with rights-cleared genuine photos/diagrams where appropriate.
- Use an explicit scene graph: each shot records narration start/end, source, asset paths, motion grammar, camera, masks, keyframes, audio cues and quality checks.
- Pick animation modules based on **subject**: Bang Motion (software/UI), Vox-like evidence collage (documentary/news), Huashu (science/artistic explainers), Claude Drawing (procedural diagrams), Stickman (human stories); use only installed/verified runtimes and never imply missing third-party skills executed.
- Animated objects must **do something meaningful** matching narration: route a data pulse, show a real interface state change, reveal internal mechanism, cut/rejoin a cable, evolve a true chart, etc.
- One visual style anchors the film; secondary styles only when there is a specific storytelling reason.
- **Mandatory kinetic-text storyboard:** for each scene list the exact concise explanatory label, its factual role, entry and exit motion, animation start/end time and what object or mechanism it highlights. Animated titles, short explainers, arrows, counters and diagram text MUST appear in the real MP4, not merely the storyboard; never replace them with generic word-for-word TTS captions.

## 04. Hard technical QA gate

- Output native **1080×1920+**, 9:16, H.264 and AAC, 30 FPS or more (60 FPS preferred when feasible). **No 720p or 540p masters and no upscaled lower-resolution substitutes.**
- MUST INCLUDE meaningful animated explanatory typography in every Reel: a moving hook headline, readable short object labels, crucial fact callouts, moving diagram annotations and a punchy visual takeaway. These are not transcript captions: never burn line-by-line narration words, karaoke, SRT/VTT or verbatim speech subtitles. Text must add explanation, not repeat speech. Plan at least five distinct mobile-safe, genuinely animated typographic beats in a 30–60 second Reel (sliding/masked reveals, counters, moving pointers, tracked labels), use CTRL PULSE branded colors and inspect them in sampled frames. A video without these text elements FAILS QA.
- Decode the completed MP4, inspect representative frames **and every transition** for freezes, clipping, distorted faces, strange UI details, broken masks, art inconsistencies, improper safe areas or black sections.
- Listen to the final mixed sound; make sure the generated TTS spans all required beats and SFX line up with the actual actions.
- Reverify every factual claim, image-rights record, real-vs-synthetic disclosure, and caption sources.

## 05. Feed and Story art

- **Feed:** 4:5 branded graphic, one useful accurate takeaway, English caption with primary-source link(s), CTA, and no unrelated Reel subject repetition.
- **Story:** 9:16 image with one direct and readable tip, teaser or genuine audience question. Safe area and contrast must be optimized for phones. No suspicious or functional generated QR links.
- CTRL Pulse editorial palette: forest ink `#152723`, warm paper `#F2EEDD`, signal orange `#F36642`, citron `#D8EE6D`, sage `#A9B4A8`. Use tasteful subject-appropriate cinematic color, **not the same generic neon montage for everything**.

## 06. Publishing and verification

1. Confirm active publishing account and exact CTRL Pulse Page ID.
2. Stage finalized media to authorized reachable HTTPS hosting, verify uploaded file dimensions, duration and codec.
3. Publish the **Reel as REEL**, feed image as **POST**, and vertical image as **STORY**; if a Story connector only supports scheduling, use earliest feasible **same-day** time, not future-day scheduling in lieu of publishing.
4. Poll each publishing request to completion; then independently **read back the Page media/feed** for the Reel and image post and use Facebook's exact permalink.
5. For Stories, verify platform/Metricool state and, when supported, Facebook Story presence. Be explicit if Page-level confirmation isn't available.
6. Keep individual statuses as **DRAFT / QA-PASSED / QUEUED / SCHEDULED / PUBLISHER-SUCCESS / FEED-VERIFIED / FAILED**. Never call `PENDING` or `SCHEDULED` live.
7. Do not retry an ambiguous upload until duplicate IDs and actual Page feed have been checked.

## 07. Daily record

Maintain a manifest and downloadable output pack with:
- three topics and their source URLs;
- Reel script, TTS identity/duration, beat timing, images/asset sheets and exact used layers;
- real media and licensing notes;
- Reel master file metadata and technical/visual QA;
- three separate post IDs, publishing states, verified Facebook links, and failures.

**End-of-run report:** use one concise table for Reel / Feed / Story with **created / pending / published / readback verified** and exact links, followed by blockers if any. If a Reel fails, never replace it with a text-only post and call the daily goal complete.

## 08. Weekly improvement loop

Review Reel view duration/completion, retention hook, shares, saves, follows, meaningful comments and source-link performance. Identify winning **narratives and subject fit**, not repetitive generic visual templates. Run one new storytelling/motion experiment each week.
